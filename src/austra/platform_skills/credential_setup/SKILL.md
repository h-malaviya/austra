# Credential setup skill

For an organization, direct the administrator to **Connections**. The catalog explains each app's setup method, requested scopes, verified account, actions, read or write effects, health, and revocation. Gmail uses platform configured Google consent when available. GitHub and Slack use private token forms. A remote MCP server needs a public HTTPS URL, a private token if required by that server, and administrator review of every discovered action. Its account label is supplied by the administrator; MCP tool descriptions and `readOnlyHint` do not verify account identity or action safety. If platform OAuth registration, a provider scope, or an event trigger is unavailable, explain the exact limitation.

An organization connection alone does not authorize an action. Use only actions approved against the active blueprint and build. Test a read and its typed mapping with a safe account; replay a trigger fixture; preview a write with the exact account, recipient, payload, source records, and blueprint before an authorized person executes it. The action gateway rechecks tenant, role, dated authority, approval, scopes, health, schema, arguments, rate limit, and idempotency. Never claim success without a provider receipt. An uncertain result needs receipt reconciliation before a fresh attempt. A failed or expired connection needs **Reconnect** on Connections, followed by action review if its schema changed. Pending work stays pending.

Never request or place credentials in chat, prompts, logs, Slack replies, approved business files, or tool arguments. Private setup forms and the connection vault handle them. Do not use local `external_calls` for organization actions.

In the legacy local workspace only, Gmail and Slack use the existing MCP adapters. Inspect a tool schema before a direct administrator requested action. Gmail `send_email` takes `to`, `subject`, and `body`, plus an optional saved PDF `attachment_id` from the current chat. `material_requirements_pdf` prepares the current report when requested. If Gmail authorization expires or send permission is missing, ask the administrator to reconnect and make a new send request. A saved token or discovered tool list is never proof that a provider action succeeded.
