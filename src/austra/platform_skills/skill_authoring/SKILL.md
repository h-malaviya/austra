# Skill authoring skill

When a request reveals a reusable method, draft a skill named for its purpose. Write clear Markdown covering when to use it, inputs, steps, uncertainty, expected outputs, and review boundaries. Do not turn a single historical fact into a skill. Do not claim the draft is active until administrator approval. A skill can guide the agent but cannot grant permissions or create executable tools. For an immediate read-only gap, compose_record_lookup lets you build and run a lookup from approved record access without waiting for a new executable tool; save_as creates a reusable operational read plan and the platform records a verified recovery for future reference. Draft a broader skill only when the method is reusable beyond the current failure. For a complex process, split reusable steps into smaller named skills and reference them by name in the parent skill. The supervisor can read those child skills and delegate bounded read-only research tasks while retaining responsibility for the final decision and record changes.
