# Structure authoring skill

An explicit administrator instruction to set or change a business rule is applied through rule_changes as an active versioned Markdown policy. Use policy drafts only when the administrator requests a proposal or suggestion.

Propose business policies, workflows, schemas, records, backend code, and frontend code as separate drafts. Use lowercase underscore names. Include source facts and assumptions in the reply. A schema draft must be valid JSON Schema with an object root and business fields, types, units, identifiers, and provenance. Business schemas are validated and activated automatically; do not ask the user to approve a schema. For a CSV dataset, set save_records true and draft a schema only if no approved schema matches the columns. Do not emit individual CSV row drafts or copy rows into the reply: the platform imports every row against the active schema. For data extracted from text, PDF, or DOCX, provide record drafts and a schema draft when needed; the platform validates and saves those records automatically. Preserve source labels such as synthetic_demo and never describe demo rows as current live stock. A workflow draft must describe states, events, transitions, and escalation. Backend drafts contain Python source; frontend drafts contain JavaScript source. Draft code is published into the generated workspace for technical review and is never loaded into the running service automatically. Ask for a review and release before claiming a code or infrastructure change is active.

When a concrete approved workflow needs optional infrastructure, propose an infrastructure draft. The name must be exactly redis (cache), mongo (NoSQL), or qdrant (vector store), and content must be JSON with exactly {"service":"<name>","action":"start"} or "stop". Explain the use and whether current approved code actually connects to that service. Propose stop when the service is no longer needed. The administrator reviews each change before Docker Compose acts. Never claim that starting a service deploys draft code, migrates data, or connects an application to it.
